## Commands

```bash
npm install       # install dependencies (runs `prisma generate` via postinstall)
npm run dev       # start the dev server (Turbopack) at localhost:3000
npm run build     # production build
npm run start     # run the production build
npm run lint      # ESLint

npm run db:push     # push prisma/schema.prisma to the database (no migration file)
npm run db:migrate  # create + apply a Prisma migration
npm run db:studio   # open Prisma Studio
```

There is no test runner configured yet.

Set `DATABASE_URL` in `.env` (see `.env.example`) before running anything that touches the database. `prisma.config.ts` loads it via `dotenv/config`.

## Architecture

- Next.js App Router, TypeScript, Tailwind CSS v4. Routes/pages live under `src/app`.
- Prisma is the data layer. Schema is `prisma/schema.prisma`; the generated client is emitted to `src/generated/prisma` (gitignored, regenerated by `prisma generate`/`npm install`) rather than `node_modules/.prisma`.
- `prisma.config.ts` (not `schema.prisma` datasource env blocks) is where the `DATABASE_URL` is wired up for the Prisma CLI.

## Communication style

- Write in clear, conversational English; use simple words where possible.
- Avoid buzzwords, corporate jargon, and vague statements.
- Focus on practical examples and actionable insights; prioritize clarity over sophistication.
- Explain concepts as if speaking to an intelligent beginner.
- Use short paragraphs and strong structure.

## Rules

- Ask at least 3 clarifying questions before starting any complex task.
- Present a plan before execution.
- Never make assumptions when important information is missing — ask instead.
- Keep outputs concise and relevant; don't pad content to increase length.
- Use practical examples whenever possible.
- Stay within requested word counts and formats.
- When multiple approaches exist, explain the tradeoffs.
- If uncertain, ask before proceeding.
- Review outputs before final delivery.

## File naming rules

- Use lowercase file names.
- Use hyphens instead of spaces.
- Use descriptive names.
- Avoid special characters.

## Agent behavior

Before starting any task: (1) understand the objective, (2) ask clarifying questions if needed, (3) create a plan, (4) execute step by step, (5) review the output, (6) improve weak areas, (7) deliver the final result.

Use connected integrations (see Claude Code settings) whenever necessary for execution. If a task needs a connector that isn't already connected, confirm with the user before requesting it.
